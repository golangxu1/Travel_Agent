## 维度一：性能效率

### 指标

| 指标 | 说明 | 采集方式 |
|------|------|----------|
| 总耗时 | 从请求到全部完成 | 追踪系统 /api/traces |
| 阶段1并行耗时 | 3个Agent并行的实际耗时 | trace spans |
| 首屏到达时间 | 第一个模块返回前端的时间 | 前端计时 |
| 总Token消耗 | input_tokens + output_tokens | trace spans |
| 并行加速比 | 串行理论耗时 / 实际耗时 | 计算得出 |

### 方法

每个样本跑 1 次，记录追踪数据，取 10 次平均值。

---

## 维度二：POI 命中率

### 指标

| 指标 | 说明 |
|------|------|
| POI总数 | 行程Agent输出的景点数量 |
| 坐标命中数 | 高德API能查到坐标的数量 |
| 图片命中数 | 高德API能查到图片的数量 |
| 坐标命中率 | 坐标命中数 / POI总数 × 100% |
| 图片命中率 | 图片命中数 / POI总数 × 100% |

### 方法

从返回的 itinerary_pois 数据中统计：
- location 非空 → 坐标命中
- photo 非空 → 图片命中

## 维度三：内容质量（人工评分）

### 评分标准（每项 1-5 分）

| 评分项 | 1分 | 3分 | 5分 |
|--------|-----|-----|-----|
| 信息准确性 | 景点/餐厅不存在或信息错误 | 大部分准确，少量过时 | 全部真实可查 |
| 实用性 | 笼统建议，无具体信息 | 有部分具体信息 | 有店名、价格、时间等具体信息 |
| 行程合理性 | 路线绕远、时间冲突 | 基本合理，偶有不顺 | 地理聚集、时间充裕、动线流畅 |
| 预算可信度 | 数字明显离谱 | 大致合理 | 有计算过程，数字可验算 |
| 个性化匹配 | 完全没体现偏好 | 部分体现 | 行程、餐厅、景点都匹配用户偏好 |

### 方法

对 10 个样本的 5 个模块分别打分，总分 = 5项 × 5分 = 25分/样本。

## 维度五：局部重生成效率

### 方法

对 5 个模块各触发一次重生成，记录：

| 指标 | 说明 |
|------|------|
| 重生成耗时 | 单模块重跑的耗时 |
| 全量生成耗时 | 完整跑一次的耗时 |
| 节省比例 | (全量 - 重生成) / 全量 × 100% |
